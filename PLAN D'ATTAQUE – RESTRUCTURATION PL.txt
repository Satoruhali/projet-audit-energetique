Phase 3 : Algorithme de sélection (2 étapes)
Étape 3.1 — Version isolée avec tests unitaires
Durée : ~2h  
Livrable : Module backend/services/algorithme-selection.js + tests
À coder AVANT toute intégration API. Pourquoi :
- L'algo est complexe (meilleure combinaison couvrant typologies + plancher bas + plancher haut + position)
- Il doit être testé exhaustivement sans dépendance réseau
- Il peut être développé en parallèle de la Phase 2
Fonctions minimales :
class AlgorithmeSelection {
  // Entrée : liste de logements avec leurs caractéristiques
  // Sortie : liste des logements sélectionnés + métriques
  
  calculerSeuil(nbLogements)     // RG15 : 10% ou 10+5%
  grouperParCriteres(logements)  // Regroupe par (typo, plancher_bas, plancher_haut, position)
  trouverMeilleureCombinaison(groupes, seuil) // Set cover pondéré
  selectionner(logements)        // Point d'entrée unique
}
Tests unitaires (mocha/jest) :
- 10 logements → seuil = 1 (10%)
- 50 logements → seuil = 5 (10%)
- 100 logements → seuil = 10+5 = 15 (10% + 5%)
- Couverture exhaustive de toutes les typologies
- Cas où tous les logements sont identiques (même typo, même plancher)
- Cas avec logements intermédiaires uniques
Indépendant de : Peut être fait en parallèle des Phases 1-2
